# Prompt 迭代记录（v1 → v2）

> 目标：把"能写出报告"变成"写出**可核对**的报告"。版本都保留在 `market_scout/prompts.py`，`SCOUT_PROMPT_VERSION=v1|v2` 切换，评测脚本按版本跑。

## 1. v1 的四个问题

| # | 问题 | 现象 |
| --- | --- | --- |
| P1 | researcher 只说"先抓取再总结"，没有要求引用 | 报告里的价格/功能没有任何 `[S#]`，无法核对；错也不知道错在哪一步 |
| P2 | 没有"查不到怎么办"的指令 | 页面抓取失败时模型凭记忆补全，出现上下文里根本不存在的功能描述 |
| P3 | 没有"不要重复动作"的指令 | 同一 URL 被反复 `fetch_page`，直到步数耗尽；页面预算被迅速烧光 |
| P4 | planner 只说"拆成不超过 3 个子问题" | 容易拆出"背景/现状/趋势"这类不可检索的泛话题，子任务空转 |

## 2. v2 改了什么

| 版本 | researcher | writer | critic |
| --- | --- | --- | --- |
| v1 | "先抓取页面，再检索证据，最后用 3-5 句话总结" | "根据笔记写一份简短的报告" | "检查有没有没依据的说法"（自然语言输出） |
| v2 | 三条纪律：**先证据后结论 / 每条事实带 `[S#]` / 同一动作不重复超过两次**；并区分静态页与需渲染页 | 只用给定证据；固定"结论 / 分项发现 / 证据来源"三段；每条事实带 `[S#]`；证据不足显式标注 | 逐句核对事实是否被 `[S#]` 支撑，只输出 `{"issues": []}` 结构化 JSON |

配套的**代码级约束**（不依赖模型自觉）：
- `critique` 节点先做规则校验：引用编号必须出现在本次 run 的 `source_id` 集合里，否则记为 issue；
- `revise` 最多一次，避免"改到天荒地老"；
- 事件流记录 `loop.detected` 与 `draft.written`，Prompt 改动的影响可以从事后回放里定位。

## 4. 这份 A/B 为什么没有区分度（必须诚实说明）

`MockLLM` 是确定性脚本：它**不读 Prompt**，只按"先 `search_evidence`、再基于 hits 拼结论"的固定路径行为。因此：

- 离线 A/B 只能证明**评测口径与链路是稳定的**（同输入同输出，可用于回归），不能证明 v2 更好；
- 真正能区分 v1/v2 的是**真实模型的引用率、无依据句子比例、重复工具调用次数**。

这也正是保留 Mock 的原因：它把"链路问题"和"模型问题"分开——链路必须 100% 稳，模型效果再用真实 Key 单独测。

## 5. 下一步（真实模型的 A/B 口径）

1. `SCOUT_LLM_PROVIDER=openai` + 网关 Key，同一个数据集跑 v1/v2 各 1 轮；
2. 关注三个新指标：`citation_rate`（有引用段落占比）、`unsupported_claim_rate`（critique 报出的无依据句 / 总句数）、`dup_tool_calls`（同工具同参数重复次数）；
3. 判定标准：引用率提升且成功率不退，才算 v2 有效；否则回退。
